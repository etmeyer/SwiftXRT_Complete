# Re-running after the October 2026 changes

In early October 2026 every step of the pipeline was documented and tested
end to end, and what turned up was fixed. If you ran the pipeline before
then, this page says what to run again. Each step's page has the details.

## In short

- **Keep** your downloads (Step 2) and the xrtpipeline output (Step 3).
- **Re-run Steps 5–8.** The pile-up radii, the WT checks, the extraction
  and the fits have all changed, so every flux and photon index changes.
- **Keep your edited master tables.** Make the WT table again under a new
  name and compare (below).

## What to run

In the HEASoft terminal (`setup_swiftxrt; heainit`), with your source's
position:

```bash
cd XRT_output
swift_xrt_king_profile.py --ra 187.2779 --dec 2.0524      # 5a: new pile-up radii
swift_pc_source_viewer.py                                 # 5b: images (optional)
swift_wt_summary_viewer.py --ra 187.2779 --dec 2.0524     # 6a
make_wt_master_table.py --output wt_master_table_new.txt  # 6b, then compare:
diff wt_master_table.txt wt_master_table_new.txt
parallel_extract.py --ra 187.2779 --dec 2.0524 --nproc 16 # 7
```

Then in the CIAO terminal (`setup_swiftxrt; ciao`):

```bash
cd XRT_output
parallel_fit.py --nh 0.0179 --caldb /opt/CALDB --nproc 16 # 8
```

Before you extract:

- **Look at the new pile-up radii before keeping hand-set ones.** If you
  have a `pileup_overrides.txt`, its radii still win over the automatic
  ones. Step 5a now finds radii that agree with spectral fits, so check
  `king_profiles.pdf` and delete the overrides you no longer need, then
  re-run 5a.
- **Keep `pc_master_table.txt` as it is.** Re-running the Step 5c one-liner
  would overwrite your edits.
- **Copy your WT edits into the new WT table** if `diff` shows rows that
  changed `include` (for example a pointing whose target is outside the WT
  strip, now excluded automatically), then use it as `wt_master_table.txt`.
- If you ran Step 3 with `--createexpomap no`, run it again without that
  option: Steps 5 and 7 need the exposure maps.

## What changed

| Step | Change | Effect | PRs |
| ---- | ------ | ------ | --- |
| 1 | Two terminals: HEASoft for Steps 2–7, CIAO for Step 8; each script says which one it needs | Running everything in one terminal had failed | [#6](https://github.com/etmeyer/SwiftXRT_Complete/pull/6) |
| 2 | Download fixes: where the auxiliary files go, `--list-only` with `--obsid` | None on the data | [#3](https://github.com/etmeyer/SwiftXRT_Complete/pull/3), [#7](https://github.com/etmeyer/SwiftXRT_Complete/pull/7), [#8](https://github.com/etmeyer/SwiftXRT_Complete/pull/8) |
| 3 | `xrt_pipeline.py` runs reliably in batch (private parameter files, timeouts), reports failures and checks its products | None on the products | [#5](https://github.com/etmeyer/SwiftXRT_Complete/pull/5), [#12](https://github.com/etmeyer/SwiftXRT_Complete/pull/12) |
| 4 | The survey shows each pointing's target and offset | Flags pointings of other targets | [#13](https://github.com/etmeyer/SwiftXRT_Complete/pull/13) |
| 5 | Pile-up radius from the PSF's surface brightness, on profiles corrected for bad columns; RA/Dec converted to pixels correctly far from the equator | New radii (3C 273: 13.7–18.5″), fluxes consistent with spectral fits; at Dec +71° the profile had been built on empty sky | [#11](https://github.com/etmeyer/SwiftXRT_Complete/pull/11), [#14](https://github.com/etmeyer/SwiftXRT_Complete/pull/14), [#15](https://github.com/etmeyer/SwiftXRT_Complete/pull/15) |
| 6 | WT source detection; the same RA/Dec fix | Pointings with the target outside the strip are excluded; at Dec +65° a bright source had been "not detected" | [#10](https://github.com/etmeyer/SwiftXRT_Complete/pull/10), [#15](https://github.com/etmeyer/SwiftXRT_Complete/pull/15) |
| 7 | Each ARF built from its own exposure map; parallel runs no longer drop observations or lose the ARF; long folder paths work | 34 of 82 WT fluxes in 3C 273's first epoch changed by −24% to +13% | [#6](https://github.com/etmeyer/SwiftXRT_Complete/pull/6), [#9](https://github.com/etmeyer/SwiftXRT_Complete/pull/9), [#16](https://github.com/etmeyer/SwiftXRT_Complete/pull/16), [#17](https://github.com/etmeyer/SwiftXRT_Complete/pull/17) |
| 8 | W-stat instead of χ²; short spectra frozen at the source's median Γ instead of 2.0; `wilm` abundances; 1σ errors | Band fluxes +3–7%, 1 keV fluxes +1–5%, Γ −0.02; error bars on Γ and the 1 keV flux 1.6× smaller | [#18](https://github.com/etmeyer/SwiftXRT_Complete/pull/18) |

Two of these could have made earlier results quietly wrong, not just a
little off:

- **Parallel extraction** before PRs #6 and #9 sometimes skipped
  observations without saying so, and wrote spectra whose ARF and background
  links pointed to deleted folders, so the fits ran without them.
- **Sources far from the celestial equator**: Steps 5 and 6 converted the
  position to pixels without the cos(Dec) factor, so they could look for the
  source in the wrong place. At Dec +65° and +71° they did.
